# 문서 지식베이스 (kb)

> 문서를 **글·표·그림·엑셀** 네 채널로 분해하고, **업종별**로 분류해 적재한다.
> 적재 전에 **개인정보보호법·인공지능 기본법** 준수를 결정론적 규칙으로 검토한다.

LLMWiki 의 세 번째 그래프다.

| 모듈 | 대상 | 그래프 | 판정 주체 |
|---|---|---|---|
| `llmwiki/` | 레거시 소스 코드 | 온톨로지 v1.0 (static/derived/llm) | 파서 |
| `llmwiki/compliance/` | 조직의 규정·통제 | 규제 지식그래프 v1.0 (collected/llm/human/rule) | 룰 + 사람 확정 |
| **`llmwiki/kb/`** | **업무 문서(PDF)** | **문서 온톨로지 v0.1 (measured/documented/assumed/computed)** | **룰 + 사람 확정** |

핵심은 같다 — **LLM 은 그래프를 채우고, 판정은 그래프 위의 룰이 한다.**
이 모듈은 LLM 을 아예 부르지 않는다.

---

## 왜 채널을 나누는가

문서를 통짜 텍스트로 뽑으면 **표의 행 구조가 깨진다.** 에너지진단 보고서 32면으로
실측하면:

| | 결과 |
|---|---|
| 표 데이터 행 | 95개 |
| **행 구조(셀 순서·인접)가 보존된 행** | **21개 (22%)** |
| 구조가 깨진 행 | 74개 (78%) |

숫자 자체는 텍스트 스트림 어딘가에 남는다. 사라지는 것은 **"어느 행 어느 열의
값인가"** 다. `18대 | 22kW | 25.7kW | 7,200h | 80% | 2,664,576kWh` 가 의미를 잃는다.
진단 보고서는 수치가 전부 표에 있으므로, 이 상태로는 검색이 문서의 절반만 본다.

| 채널 | 무엇 | 앵커 | 쓰임 |
|---|---|---|---|
| `text` | 문단·서술 | page | 문제점·개선방안 검색 |
| `table` | 셀 그리드 | page + table_idx + (row,col) | **모든 수치의 출처** |
| `image` | 사진·도면·차트·로고 | page + image_idx | 증적, 명판 OCR(v0.2) |
| `excel` | 표 전체를 시트로 | sheet = `p{page}_t{idx}` | 감리 제출, 재계산 |

표는 **표 단위로 통째 청킹**한다. 문장처럼 자르면 행-열 관계가 다시 깨진다.

`llmwiki/compliance/docparse.py` 와 목적이 다르다. 저쪽은 규정 문서를 하나의 평문
좌표계로 펴서 근거 스팬의 기준을 만든다(조문 앵커가 목적). 여기는 격자를 살린다.

## 입력 형식 — PDF · 엑셀 · 이미지

진단 자료가 PDF 만 오는 것은 아니다. 계측 데이터는 **엑셀**로, 설비 명판과 현장
사진은 **이미지**로 온다. `sources.py` 가 형식을 가리고, 뒤쪽(분류·게이트·온톨로지·
위키)은 `ParsedDocument` 하나만 본다.

| 형식 | 어떻게 읽는가 | 한계 |
|---|---|---|
| `.pdf` | `parse.parse_pdf` 4채널 | 스캔본은 텍스트 레이어가 없어 빈 결과 |
| `.xlsx` `.xlsm` `.csv` `.tsv` | 시트 = 쪽, 빈 줄로 끊어 표 블록 | 2,000행 초과분은 자른다(경고 남김) |
| `.png` `.jpg` `.webp` … | 그림 채널 + OCR 있으면 글 | **OCR 없으면 글자를 못 읽는다** |

엑셀에서 신경 쓴 것 셋.

* **수식은 저장된 계산값으로 읽는다**(`data_only=True`). 수식 문자열(`=B2*C2`)이 값으로
  들어가면 수치 검산이 통째로 무의미해진다. 계산값이 비어 있으면 **수식이 실제로 있는
  칸만 세어** 경고한다 — '빈 칸이 많다'로 짐작하면 서식만 잡힌 성긴 시트가 전부 경고를 받는다.
* **빈 줄로 표를 끊는다.** 한 시트에 제목 몇 줄, 표, 빈 줄, 또 표가 이어지는 형태가
  흔하다. 통째로 한 표로 만들면 헤더가 엉뚱한 줄이 되어 모든 열 이름이 틀어진다.
* **서식용 빈 열은 접는다.** 남겨 두면 헤더가 `['', '', '항목']` 이 되어 열 이름으로
  표를 찾는 추출기가 헛돈다.

이미지는 두 단이다 — 파일을 여는 것(Pillow)과 글자를 읽는 것(OCR). 앞은 되고 뒤는 안
되는 상태가 정상적으로 있을 수 있어 `/api/kb/health` 가 **형식별로** 알린다. OCR 이
없으면 화면이 업로드 전에 경고하고, 분석 결과에도 "읽지 못했다"를 남긴다 — 빈 결과를
주면 '아무것도 없는 사진' 과 '읽지 못했다' 가 구분되지 않는다.

OCR 을 켜려면:

```bash
uv pip install pytesseract
sudo apt install tesseract-ocr tesseract-ocr-kor     # Ubuntu
brew install tesseract tesseract-lang                # macOS
```

## 파이프라인

게이트를 건너뛰는 경로가 없다. 우회로를 만들면 언젠가 그 경로로 나간다.

```
PDF ─▶ 4채널 파싱 ─▶ 업종 분류 ─▶ 필수지표 커버리지
                                  │
                                  ▼
                         적재 게이트 (개인정보/AI기본법)
                                  │
                    blocker 있으면 ─┴─▶ 중단. 적재하지 않음
                                  │
                                  ▼
                         비식별 처리 + 마스킹 검산
                                  │
                                  ▼
                  업종 구획(ediag__waste 등)에 채널별 적재
                                  │
                                  ▼
                            온톨로지 그래프 + TTL
```

| 파일 | 역할 |
|---|---|
| `parse.py` | pdfplumber 기반 4채널 분해, 엑셀 내보내기, 청킹 |
| `taxonomy.py` | 업종 12종 닫힌 집합 + 업종별 필수지표·원단위 기준 |
| `classify.py` | 규칙 기반 업종 분류 + 필수지표 커버리지 |
| `gate.py` | 개인정보 탐지·비식별·검산 + AI기본법 점검 |
| `ontology.py` | 4채널 → 그래프(노드/엣지) + 스키마 검증 + TTL |
| `ingest.py` | 분석 파이프라인 (적재하지 않는다) |
| `store.py` | 업종 구획별 적재·검색 + append-only 적재 이력 |
| `cli.py` | `llmwiki kb …` |

## 업종이 분류 축인 이유

`taxonomy.py` 의 업종 12종은 **닫힌 집합**이다. 여기 없는 업종은 그래프에 나올 수
없고, 새 업종이 필요하면 먼저 이 파일을 고쳐야 한다.

업종을 자유 문자열로 두면 같은 보고서가 적재마다 다른 라벨을 받고, 그 순간 업종별
필터와 업종별 벤치마크가 전부 무의미해진다.

```python
SectorProfile(
    code="waste", name="폐기물처리·자원순환", ksic="E38",
    required_metrics=("annual_electricity_kwh", "moisture_stage", ...),
    unit_basis="처리량 1톤당",          # ← 업종마다 원단위 분모가 다르다
    key_equipment=("건조기", "보일러", "송풍기", ...),
)
```

`required_metrics` 가 이 모듈의 실질이다. **업종을 알면 무엇이 빠졌는지를 결정론적으로
물을 수 있다.** 규제 지식그래프의 커버리지 갭 분석과 같은 발상이다.

`unit_basis` 때문에 업종을 섞으면 안 된다 — 건물은 ㎡당, 폐기물처리는 처리톤당이라
벤치마크가 호환되지 않는다.

### 분류는 규칙이 한다

1. 어휘 규칙으로 점수 (등장 횟수의 **제곱근** — 한 단어 100번보다 10종 1번이 이겨야 한다)
2. 1·2위 격차가 25% 이상이면 확정
3. 애매하면 확정하지 않고 `needs_review=True` 로 사람에게 넘김

정밀도 우선이다. 잘못 분류된 문서는 영영 엉뚱한 구획에서 검색된다 —
**틀린 라벨은 없는 라벨보다 나쁘다.**

## 적재 게이트

### 개인정보보호법 — 목적지가 판정을 가른다

문서를 국외 사업자의 모델로 보내면 개인정보가 있는 한 그것은 **국외 이전**이다
(제28조의8). LLMWiki 는 공급자를 화면에서 바꿀 수 있으므로 **해당성이 고른 공급자에
따라 달라진다.**

| 공급자 | 목적지 | 국외 이전 |
|---|---|---|
| `ollama` | 사내 GPU | 비해당 |
| `template` | 로컬 템플릿 | 비해당 |
| `claude` | Anthropic (미국) | 해당 |
| `grok` | xAI (미국) | 해당 |
| 그 밖 | 미등록 | **해당으로 간주** (모르는 것은 막히는 쪽으로 틀린다) |

`config.yaml` 의 `kb.destination` 으로 고정할 수 있고, 비워 두면 `llm.provider` 를 따른다.

진단보고서에는 **거의 항상** 담당자 성명·연락처가 있다. 따라서 국외 목적지에서
`upload_allowed_raw` 는 거의 항상 `False` 이고, 실제 적재 경로는 비식별 처리를
반드시 거친다.

마스킹은 값을 지우지 않고 **종류를 남긴 토큰**으로 바꾼다.

```
담 당 자 : 허 만 수  (063)635-8991  vitech1200@naver.com
  ↓
담당자: [성명] [전화번호] [이메일 주소]
```

`[전화번호]` 가 남아야 "여기에 연락처가 있었다" 는 사실이 검색·감리에서 보존된다.
그리고 마스킹 결과를 **다시 탐지기에 넣어 검산한다**(`verify_masking`). 게이트를 믿지
않고 검산한다 — 잔존이 있으면 적재를 막는다.

한글 문서의 자간 조판(`허 만 수`)을 견디지 못하면 탐지 자체가 무의미하므로, 직위·성명
양쪽 모두 공백을 허용하는 패턴을 쓴다. 오탐도 관리한다 — 폐기물 분류코드 `51-38-01`
은 계좌번호가 아니다. 준수 도구에서 오탐은 비싸다.

주민등록번호 같은 고유식별정보는 `UNMASKABLE_RULES` 라 **마스킹해도 적재되지 않는다.**

### 인공지능 기본법 (시행 2026.1.22)

| 조항 | 점검 | 본 시스템 |
|---|---|---|
| 제31조제1항 | 생성형 AI 사전 고지 | 지식베이스 화면 상단 상시 고지 |
| 제31조제2항 | 생성물 표시 | 결과 하단 고정 표기 |
| 제34조 | 고영향 사업자 의무(인적 감독 등) | 확정 단계 서명 (`llmwiki reg`) |
| 제2조제4호 | **고영향 해당 여부** | **판단 유보** — 룰이 확정하지 않음 |
| 제32조 | 안전성 확보 의무 | 비해당 추정 (응용 서비스) |

고영향 해당성은 정성 판단이라 룰이 답할 수 있는 질문이 아니다. 판단에 필요한 사실만
모아 사람에게 넘긴다 — 규제 지식그래프의 L3 유보와 같은 처리다.

**모든 `Finding` 의 `resolution` 은 비어 있다.** 판정은 룰이, 확정은 사람이 한다.
룰이 채운 `resolution` 은 `validate_graph()` 가 오류로 잡는다.

## 온톨로지

### ★ 단일 실패 지점 — ID 에 좌표를 넣지 마라

규제 지식그래프가 "조문 번호를 ID 로 쓰면 개정 때 전부 깨진다" 를 단일 실패 지점으로
지목한 것과 **같은 함정**이 여기 있다.

PDF 파서를 고치면 셀 병합·회전 도면 해석이 달라져 bbox 가 밀린다. 좌표를 ID 로 쓴
그래프는 그 순간 **전부** 끊긴다. 초기에 놓치면 파서를 한 번도 개선할 수 없다.

그래서 ID 는 의미 기반이고, 좌표는 `EvidenceSpan` 의 속성으로만 산다.
`test_node_ids_contain_no_coordinates` 와 `validate_graph()` 가 이 결정을 지킨다.

### 근거 등급 4단

PDF 에 `static` 은 존재할 수 없다. 출처가 아니라 **근거 강도**를 기록한다.

| derivation | 뜻 | 예 |
|---|---|---|
| `measured` | 현장 계측기 실측 | 25.7 kW |
| `documented` | 청구서·명판·계약·법정계수 | 1,897원/kg |
| `assumed` | 가정·설계치·카탈로그 | 부하율 60% |
| `computed` | 위 셋에서 기계 계산 | 3,989,376 kWh |

감리에서 "어디까지 믿을 수 있나" 를 물으면 **`assumed` 만 검토 대상**이라고 답할 수 있다.

### 수치 추출 규칙

단위가 **숫자에 붙어 있을 때만** 양으로 인정한다. 셀 전체에서 단위를 따로 찾으면
`남원시` 의 `원` 을 화폐로, `2015년 9월` 의 `년` 을 기간으로 읽는다. 셀이 순수 숫자면
헤더의 단위를 빌려 온다 — `용량(kW)` 아래 `22` 가 진단서에서 가장 흔한 표기다.

## 저장소

원 설계는 4채널 청크를 벡터 DB 에 넣었다. LLMWiki 에는 벡터 저장소가 없어서 같은
**규칙**을 파일 저장소 위에 다시 세웠다.

```
<kb.dir>/
  ledger.jsonl                    적재 이력 (append-only)
  ediag__waste/<doc_hash>/
    analysis.json                 분석 결과 (게이트 판정 포함)
    graph.json                    온톨로지 그래프
    graph.ttl                     Fuseki/SPARQL 적재용
    channels.jsonl                **마스킹된** 채널 청크 = 검색 단위
    tables.xlsx                   엑셀 채널
```

* `upload_allowed=False` 면 아무것도 쓰지 않는다. "그냥 넣기" 인자는 없다.
* `mask=False` 로 비식별을 꺼도 개인정보가 남아 있으면 적재가 중단된다.
* 업종이 디렉터리를 가르고, 검색 필터도 같은 축으로 **코드가** 건다.
* `ledger.jsonl` 은 덧붙이기뿐이다 — 어떤 문서가 언제 어떤 판정으로 들어왔는지가 남는다.

## API

```
GET  /api/kb/health                          상태 · 파서 준비 · 목적지 · 저장소 통계
GET  /api/kb/schema                          온톨로지 스키마 (닫힌 집합의 원본)
GET  /api/kb/sectors                         업종 닫힌 집합 (화면 드롭다운의 유일한 출처)
GET  /api/kb/sectors/{code}                  업종 프로파일 · 필수지표 · 구획명
POST /api/kb/analyze                         PDF → 4채널 + 분류 + 게이트 + 온톨로지 (적재 안 함)
POST /api/kb/ingest                          분석 → 게이트 → 업종 구획 적재
GET  /api/kb/documents                       적재된 문서 목록 + 통계
GET  /api/kb/documents/{hash}                문서 1건 (분석 결과 · 그래프 통계)
GET  /api/kb/documents/{hash}/graph          온톨로지 그래프
GET  /api/kb/documents/{hash}/graph.ttl      TTL
GET  /api/kb/documents/{hash}/tables.xlsx    엑셀 채널
GET  /api/kb/search?q=&sector=&channel=      채널 검색 (필터를 실제로 건다)
POST /api/kb/gate/review                     텍스트 규제 검토
POST /api/kb/gate/mask                       비식별 처리 + 검산
POST /api/kb/graph/ttl                       그래프 → TTL
POST /api/kb/graph/validate                  그래프 스키마 검증
```

`server/app.py` 에 규제 라우터와 같은 방식으로 한 줄로 붙는다. SPA 폴백보다 **먼저**
등록해야 한다.

```python
from .kb import bind as bind_kb
app.include_router(bind_kb(cfg))
```

|---|---|---|

| 사진 속 명판 값을 못 읽는다 | 설비 제원이 그래프에 안 들어옴 | v0.2 명판 OCR |
| 스캔본 PDF 미지원 | 텍스트 레이어 없으면 빈 결과 (경고는 남긴다) | v0.2 OCR |
| 계산 체인(`computedFrom`)이 없다 | 산술 검산 룰이 못 돈다 | v0.2 — **가장 큰 미완** |
| 물질수지(함수율) 미표현 | 건조 열량 이론 검증 불가 | v0.2 |
| 업종 분류가 어휘 규칙뿐 | 신조어·이형 표기에 약함 | 오분류를 테스트로 추가하며 확장 |
| 검색이 어휘 일치뿐 | 동의어·오탈자에 약함 | 본체가 벡터 검색을 갖추면 그 위로 옮긴다 |

**계산 체인이 v0.2 의 핵심이다.** 지금은 표에서 값을 뽑아 노드로 올리는 데까지고,
값들 사이의 수식(`연간사용량 = 정격 × 시간 × 부하율`)은 아직 그래프에 없다. 그게
들어와야 부하율 이중 적용이나 용량 부족 같은 산술 위반을 룰이 잡는다.
