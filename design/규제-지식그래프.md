# 근거기반 자동평가 엔진 및 규제 지식그래프 v1.0.0

> **LLM은 그래프를 채우고, 판정은 그래프 위의 룰이 한다.**

LLMWiki 본체가 "운영 소스 → 사실 그래프 → 서술" 을 하는 것과 같은 원칙을 규제 영역에
적용한 것이다. 사실과 서술을 갈라 두고, 판정은 사실 위에서 결정론적으로 계산한다.

구현은 `llmwiki/compliance/` 에 있고, 이 문서는 그 코드를 설명할 뿐이다.
스키마의 단일 원본은 [`llmwiki/compliance/ontology.py`](../llmwiki/compliance/ontology.py) 다.

---

## 왜 이렇게 만들었나

LLM 으로 준수 여부를 자동 판정하려는 요구와 "AI는 보조수단이며 최종 의사결정과 책임은
임직원이 수행한다" 는 원칙은 정면으로 충돌한다. 이 충돌을 봉합하지 않고 해소한다.

| 통상적 접근 | 문제 | 이 시스템 |
|---|---|---|
| LLM 에게 "이 항목이 준수되었나" 질문 | 판정 주체가 LLM 이 된다 | **LLM 에게 판정을 묻지 않는다** |
| LLM 여러 개를 앙상블 | 같은 프롬프트의 judge 는 오차가 상관돼 다수결 이득이 작다 | 앙상블에 의존하지 않는다 |
| LLM confidence 로 자동 처리 판단 | 자체 신뢰도가 실제 정확도를 과대평가한다 | 신뢰도를 임계값에 쓰지 않는다 |
| 사람 검토를 형식적으로 끼워넣기 | 검토자가 물량에 압도되어 형식 승인이 된다 | **판단 유보 물량 자체를 통제한다** |

모델은 문서에서 근거 후보를 뽑아 **노드·엣지 제안**으로 바꿀 뿐이다. 판정은 승인된
그래프 위에서 룰이 한다. `llmwiki/compliance/rules.py` 에 LLM 호출이 없다는 것이
이 설계의 전부이며, 테스트가 그것을 고정한다.

## 권한 3분할

| | 제안 Propose | 판정 Adjudicate | 확정 Decide |
|---|---|---|---|
| 주체 | 온프레미스 sLM | 결정론적 룰 | 사람 |
| 하는 일 | 근거 스팬 추출, 그래프 변경 제안 | 증적 존재·서명·기한·임계치 조회 | 해당성·정성 판단, 잔여위험 수용, 변경 승인 |
| 못 하는 일 | 판정·점수·등급, 승인 그래프 직접 수정 | 정성 판단, 해당성 해석 | — |

스키마 레벨에서 갈라 둔다. `NodeType.llm_proposable=False` 인 타입(Assessment,
Service, RuleSet, Agent)은 `proposer.type == "SoftwareAgent"` 인 제안에서 거부된다.

## 계층

| 계층 | 모듈 | 하는 일 |
|---|---|---|
| L0 수집 | `propose.ingest_regulation` | 문서를 조문 단위로 쪼개고 **불변 앵커**와 문자 오프셋을 부여 |
| L1 이해 | `propose.propose_obligations` | sLM 이 근거 스팬을 붙여 **그래프 변경 제안**만 만든다 |
| L2 그래프 | `store` | 승인된 사실. 삭제 없음, append-only, `as_of` 재현 |
| L3 판정 | `rules` | 승인 그래프 위의 결정론적 룰. **LLM 없음** |
| L4 검증 | `verify` | 형상 검증 · 스팬 대조 · 인용 강도 · 골드셋 회귀 · Cohen κ |
| L5 분석 | `analysis` | 커버리지 갭 · 규제 변경 영향 · 수기 의존 통제 |
| L6 결재 | `changeset` | diff 리뷰와 승인. 승인본/제안본 물리 분리 |

한 항목이 자동 판정되기까지:

```
문서 → L0 파서(문서ID+오프셋) → L1 sLM 제안(status=proposed)
     → 게이트 1: 형상·스팬 대조·인용 강도·제안 권한   (verify.validate_ops)
     → 게이트 2: 사람이 diff 리뷰 후 병합             (changeset.approve)
     → L2 승인 그래프
     → L3 결정론적 판정 → 충족 / 부분충족 / 미충족 / 해당없음 / 판단유보
     → 게이트 3: 심사자 확정 서명                     (rules.confirm)
```

## 세 개의 헌법

### 1. 근거 없는 사실 금지

문서에서 온 노드·엣지는 원문 스팬(`문서ID + 문자 오프셋 + 인용문`)을 반드시 갖는다.
스팬이 있으므로 `문서[start:end] == 인용문` 을 기계적으로 대조할 수 있다.

**환각을 막는 것은 프롬프트가 아니라 이 대조다.** 모델이 그럴듯한 문장을 지어내면
원문에서 찾을 수 없어 제안 단계에서 버려진다 (`propose.propose_obligations` 의
`text.find(quote)`), 승인 그래프까지 온 것도 `verify` 가 다시 대조한다.

둘째 겹은 **인용 강도**다. 조문이 "공개하도록 노력하여야 한다"(권고)인데 제안이
"필수 의무"라고 말하면, 문장은 인용했지만 주장이 근거를 넘어선 것이다.
어미로 강도를 재고 `주장 강도 ≤ 근거 강도` 를 요구한다 (`spans.check_citation_force`).
`노력하여야 한다` 를 `하여야 한다` 보다 먼저 걷어내는 순서가 중요하다 — 뒤집으면
모든 권고가 필수로 읽힌다.

### 2. 삭제 없음

저장소가 append-only 저널이라 삭제 연산이 아예 없다. 폐기는 `status="obsolete"` +
`replaced_by` 를 덧붙이는 것이고 원래 레코드는 남는다. 과거 판정의 근거가 사라지지
않으므로 감사 추적이 끊기지 않는다. 허용 연산은 `node.create` / `edge.create` /
`node.obsolete` / `edge.obsolete` 넷뿐이고, 나머지는 등급이 아니라 **불허**다.

### 3. 판정 재현성

모든 판정은 온톨로지·룰셋·기준·조문 **4개 버전**을 함께 기록한다. 저널의 레코드
번호(`seq`)나 시각(`as_of`)으로 그래프를 되돌릴 수 있으므로, 기준이 개정돼도
1년 뒤에 당시 판정을 그대로 재현할 수 있다.

## 스키마

노드 13종 · 관계 14종. 전체는 `llmwiki reg schema` 로 본다.

```
Regulation ─HAS_PROVISION→ Provision ─DERIVES→ Obligation ─IMPLEMENTED_BY→ Control
                                                                             │
                              ┌──────────────────────────────────────────────┤
                              ↓                    ↓                         ↓
                        TestProcedure         Evidence(요구)            Service
                       (VERIFIED_BY)          (PRODUCES)              (APPLIES_TO)
                                                   │
                                          COLLECTED_FROM→ SystemFunction
                                                              └ program_ref → LLMWiki Program

Control ─SATISFIED_BY(service_uuid, for_required)→ Evidence(제출)
Service ─ASSESSED_AS→ Assessment ─used→ Evidence·RuleSet
                                 └─wasAttributedTo→ Agent
```

매핑 술어는 NIST OSCAL 의 집합론 술어(`equivalent-to`, `subset-of`, `superset-of`,
`intersects-with`)를 쓴다. 이진(매핑됨/안됨)으로 만들면 "부분 충족" 을 표현할 수 없고,
그러면 커버리지 갭 분석이 무의미해진다.

`SystemFunction.program_ref` 가 LLMWiki 본체와 만나는 지점이다. 운영 소스에서 이미
뽑아 둔 Program 을 증적 생산 기능으로 잇는다 (`llmwiki reg link-programs`).
이 연결이 없는 통제가 곧 **수기 의존 통제 = 자동화 후보**다.

## 판정과 판단 유보

판정이 묻는 것은 셋뿐이고 셋 다 그래프 조회로 답한다.

> 증적이 있는가 · 서명되었는가 · 유효기간 내인가

지표 항목이면 하나 더: 측정값이 임계치를 충족하는가. 결론이 애매하면 판정하지 않고
**판단 유보**로 심사 큐에 넣는다.

| 트리거 | 사유 |
|---|---|
| `QUALITATIVE` | 통제의 auto_level 이 L3 — 정성 판단 필요 |
| `PARTIAL_EVIDENCE` | 필요 증적 중 일부만 존재 |
| `THRESHOLD_UNDEFINED` | 지표는 있으나 임계치가 미정의 |
| `METRIC_MISSING` | 임계치는 있으나 측정값이 없음 |
| `EVIDENCE_EXPIRING` | 증적 유효기간 만료 임박 (30일) |
| `PROVISION_AMENDING` | 참조 조문이 개정 진행 중 |
| `VERDICT_FLIPPED` | 직전 차수 판정과 결과가 뒤집힘 |
| `CITATION_WEAK` | 상위 의무의 인용 강도 검증 실패 |

**정밀도 우선**이다. 커버리지를 늘리려다 심사자가 물량에 압도되면 형식 승인이
발생하고, 그것은 통제 실효성 자체를 무너뜨린다. 시드 데이터 기준으로 커버리지 50% ·
정밀도 100% 가 나온다 — 유보한 만큼 커버리지가 내려간 것이지 틀린 것이 아니다.
`verify.run_goldset` 이 이 둘을 항상 나눠서 보고한다.

## 커밋 결재

승인 등급은 **하위호환 파괴 여부**로 가른다.

| 등급 | 범위 | 결재선 | 파괴 |
|---|---|---|---|
| G1 | 속성 보강, 근거 링크 추가, 라벨 수정 | 도메인 담당자 | no |
| G2 | 신규 조문·의무·통제, 신규 매핑 엣지 | AI거버넌스담당자 | no |
| G3 | 임계치·자동화수준·매핑 술어 변경, 노드 폐기 | 거버넌스 + 마이그레이션 계획 | **yes** |
| G4 | 기준 세트 판올림, 룰셋·온톨로지 구조 변경 | AI거버넌스협의체 | **yes** |
| ✕ | 물리 삭제 | **불허** | — |

영향분석(닿는 통제·판정·서비스 수)은 **병합 전에** 계산한다. 임계치를 바꾸면 몇 건이
뒤집히는지 결재자가 숫자로 보고 결정한다.

승인본과 제안본은 물리적으로 분리돼 있다. 판정 엔진은 승인본만 조회하므로
**제안이 아무리 쌓여도 판정에 영향이 없다** — 위키백과 Flagged Revisions 와 같은 구조다.

## 외부 규제 인텔리전스

외부에서 반입한 규제 개정 정보도 곧바로 기준이 되지 않는다. `RegChange` → `ChangeSet`
으로 결재 큐에 들어가 사람이 diff 를 보고 병합한다. 외부 반입과 sLM 제안이 **같은
승인 게이트**를 지나므로 통제 지점이 하나로 모인다.

내부망이 외부에 접속하지 않는 구성(수집·요약은 외부 세그먼트, 반입은 단방향)을
전제로 하며, **외부 LLM 없이도 전체 기능이 동작**하도록 설계했다. `--llm` 을 주지
않으면 결정론적 기준선 추출기가 같은 파이프라인을 돈다.

## 해 주는 것과 해 주지 않는 것

자동 판정률은 그래프를 깔아도 크게 오르지 않는다. 정직하게 말하면 유보를 반영해
**오히려 내려간다**. 진짜 가치는 기존 방식으로는 불가능했던 쪽이다.

- 커버리지 갭 자동 탐지 — 통제가 연결되지 않은 규제 의무
- 규제 변경 영향분석 — 조문 개정 시 영향 통제·판정·서비스 추적
- 부분 충족 표현 — 집합론 술어로 "일부만 덮는다" 를 집계
- 수기 의존 통제 식별 — 증적 생산 시스템이 없는 통제
- 기준 변경 사전 영향 평가 — 병합 전에 뒤집힐 건수 계산
- 과거 판정 재현 — 당시 4버전으로 그대로

제안할 때의 표현도 여기에 맞춘다. "AI가 평가를 자동으로 해 줍니다" 가 아니라
**"AI가 근거를 찾아 연결하고, 판정은 규칙이 하며, 결정은 사람이 합니다.
대신 지금까지 볼 수 없던 것 — 규제 커버리지 구멍과 법령 개정의 파급 범위 — 이
보이게 됩니다."**
